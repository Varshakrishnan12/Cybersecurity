````md
# Exercise 16: Exploiting IDOR (Insecure DOR - Order Tickets)

## 🎯 Objective
Learn how to use **Burp Suite** to identify and exploit an insecure application that trusts user-controlled data.

> **Note:** Although this lab is named **IDOR (Insecure DOR)**, the vulnerability demonstrated is closer to **Parameter Tampering / Business Logic Flaw**, because the client controls the ticket price.

---

## Tools Used
- Burp Suite Community Edition
- bWAPP
- Firefox / Burp Browser

---

# Lab Workflow

```text
Login to bWAPP
      │
      ▼
Select "Insecure DOR (Order Tickets)"
      │
      ▼
Choose 2 Tickets
      │
      ▼
Click Confirm
      │
      ▼
Intercept Request in Burp
      │
      ▼
Inspect Request
      │
      ▼
Notice Price = 15
      │
      ▼
Modify Price → 0
      │
      ▼
Forward Request
      │
      ▼
Server Accepts Modified Price
      │
      ▼
2 Tickets Purchased for 0 Euros
      │
      ▼
Change Security Level → Medium
      │
      ▼
Intercept Again
      │
      ▼
Price Parameter Missing
      │
      ▼
Server Calculates Price
      │
      ▼
Simple Attack Fails
```

---

# Step 1: Login

- Open **bWAPP**
- Login using:

```
Username: bee
Password: bug
```

---

# Step 2: Select Vulnerability

Choose:

```
Insecure DOR (Order Tickets)
```

Click **Hack**.

---

# Step 3: Purchase Tickets Normally

- Select:

```
Tickets = 2
```

Click **Confirm**.

Application charges:

```
30 Euros
```

Therefore,

```
Price per ticket = 15 Euros
```

---

# Step 4: Intercept Request

Enable **Burp Intercept**.

Order **2 tickets** again.

Burp captures the request.

---

# Step 5: Inspect the Request

Notice something similar to:

```
Tickets = 2

Price = 15
```

### Observation

The **browser is sending the ticket price**.

This is insecure because **price should be calculated by the server**, not supplied by the client.

---

# Step 6: Exploit

Modify:

```
Price = 15
```

to

```
Price = 0
```

Forward the request.

---

# Result

The server trusts the modified request.

Output:

```
2 Tickets
0 Euros Charged
```

Attack successful ✅

---

# Step 7: Change Security Level

Set:

```
Security Level = Medium
```

Return to **Insecure DOR (Order Tickets)**.

Intercept the request again.

---

# Observation

Now the request only contains:

```
Tickets = 2
```

There is **no Price parameter**.

This means:

- Server calculates the price internally.
- Client cannot manipulate it.

---

# Why did the attack work?

Because the server trusted client-side input.

Bad Design:

```
Browser
   │
Price = 15
   │
Server trusts it ❌
```

Attacker changes:

```
Price = 0
```

Server accepts it.

---

# Secure Design

```
Browser
   │
Tickets = 2
   │
Server
   │
Database
   │
Price = 15
```

The browser never controls the ticket price.

---

# Pentester Checklist

✔ Intercept the request

✔ Identify client-controlled parameters

✔ Modify important values

✔ Forward the request

✔ Verify whether the server validates the modified value

---

# Key Learning

- Never trust client-side values.
- Prices, discounts, user roles, balances, and permissions must always be validated or calculated on the server.
- Burp Suite is used to inspect and modify HTTP requests before they reach the server.

```

---

# Exam Points

- **Vulnerability:** Client-side Parameter Tampering / Business Logic Flaw (lab labels it as Insecure DOR).
- **Tool:** Burp Suite.
- **Issue:** Server trusted the client-supplied ticket price.
- **Impact:** Tickets could be purchased for free.
- **Mitigation:** Perform price calculation and validation on the server.
- **Price per Ticket:** **15 Euros**.
````
